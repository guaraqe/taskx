# Typer CLI

## Outcome

Replace the bare argparse command surface with a documented Typer application
that presents useful Rich help and errors while preserving taskx's existing
commands, arguments, options, output contracts, and exit codes.

## Context

The current parser exposes the full command tree but supplies almost no command
or parameter descriptions. Its generated help is therefore a list of names
without enough information to guide a user. Command handlers currently accept
`argparse.Namespace` values and are independently well tested.

## Decisions

- Add Typer as a runtime dependency using uv.
- Model the existing top-level commands and the nested
  `skill install {codex,claude,opencode}` tree as Typer commands.
- Give every command, argument, and option concise help text, and show help when
  a command group is invoked without a required subcommand.
- Preserve the command-handler boundary during this migration by translating
  validated Typer callback values into namespaces for the existing dispatcher.
  The business logic remains outside the CLI framework.
- Keep `main(argv) -> int` as the console-script boundary, including taskx error
  presentation and stable domain exit codes. Convert CLI usage failures into the
  framework's conventional exit code without exposing tracebacks.
- Retain `--json` behavior and the exact spelling and placement of all existing
  options, including `--global` after an agent installer subcommand.

## Constraints

- Python 3.11 remains the minimum supported version.
- Human-facing help may use terminal styling, but redirected output and all JSON
  command output must remain usable and deterministic.
- Global skill installation must continue to work outside a Git repository and
  without constructing the Taskwarrior adapter.
- No Taskwarrior lifecycle, project-scoping, locking, or actor semantics change.

## Verification

The migration is accepted when the full Ruff, ty, and pytest gates pass; parser
coverage demonstrates the unchanged command shapes; help tests cover useful
top-level and nested descriptions; invalid usage exits conventionally without a
traceback; and subprocess integration tests retain their current behavior.
